# Desktop 0.1.9 Design

## Product direction

Desktop 0.1.9 is a compatibility-preserving polish release. It keeps the official DSH runtime and plugin SDK boundaries intact while improving the desktop shell around them. The memorable visual is an original blue-black particle whale shown only during startup. The main application remains quiet and does not retain a continuous animation or GPU workload after the runtime is ready.

The startup surface is reduced to the line “探索未至之境”, one current-status line, a percentage, and a single progress meter. The existing orbital sphere, launch-stage list, feature pills, and secondary English paragraphs are removed. Failure recovery remains available, but only appears when startup fails. Motion follows `prefers-reduced-motion`, and the particle canvas is discarded when the startup document navigates to the DSH surface.

## Desktop integration

The desktop updater remains owned by Electron and `electron-updater`. Automatic checks continue after startup and on the existing interval. When a release is found, the app starts downloading immediately in the background without interrupting the active conversation. A renderer-safe update status API exposes only phase, versions, notes, percentage, and errors. Download completion opens an in-app glass panel with “restart and install” and “later” actions. Manual checks use the same panel for checking, current-version, progress, and error states.

The sidebar update trigger calls the desktop updater whenever the Electron bridge exists. Browser-only deployments retain the current Web UI plugin updater as a fallback. The visible Help menu and sidebar therefore converge on one desktop update flow without removing Web functionality.

## Reliability and security

Conversation copy failures are fixed at the Electron permission boundary rather than by editing official DSH source. Only `clipboard-sanitized-write` is allowed, only for the active loopback runtime origin, and all other renderer permissions remain denied. Unit tests cover the origin and permission rules.

Update state validation stays inside fixed IPC channels. Installation still stops the embedded runtime before `quitAndInstall`. Tests cover background download, renderer status publication, manual checks, deferred installation, and permission isolation.

## Bundled long-term memory

Desktop 0.1.9 includes the official `@vectorize-io/hindsight-coding-agents` package as a protected DSH bundle pinned to 0.3.4. The package uses DSH's native Cordis lifecycle and tool registry, so it does not require an MCP bridge. It scopes banks by repository and can retain completed exchanges, recall prior decisions, seed Git history, and expose knowledge-page tools.

The integration is a client, not a bundled memory database. Users still select Hindsight Cloud, a self-hosted server, or the optional local daemon and provide any required credentials. The release notes call out that the integration can transmit repository history and conversation content to the configured endpoint and that its optional codebase survey can invoke a coding-agent model.
