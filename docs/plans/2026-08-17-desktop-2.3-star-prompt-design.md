# Desktop 2.3 Star prompt and updater repair design

## Product behavior

Desktop 2.3.0 shows one repository-support prompt after the main Harness page has loaded. The prompt is claimed atomically in the Electron main process before it becomes visible, so page reloads and later launches do not show it again. Development previews can force the surface open without writing real user state. The prompt is dismissible by its close button, secondary action, backdrop, or Escape. Its primary action plays a brief local star-burst animation and then opens the official GitHub repository through the existing allowlisted Help IPC action. It does not fetch a star count, claim that a star was recorded, or require a GitHub login.

The visual treatment combines a contained announcement modal with version-scoped dismissal, a star-shaped focal illustration, restrained staggered entry, a slow orbit, a one-shot halo, button shimmer, and a short particle burst. Motion is built with CSS and DOM primitives, honors `prefers-reduced-motion`, adds no runtime dependency, and remains legible in both Harness light and dark themes. A secondary community action opens the existing controlled QQ community window so users always have a visible bug-feedback route without weakening the repository action or exposing arbitrary URLs.

## Update repair and verification

The NSIS process check uses electron-builder's single `customCheckAppRunning` hook instead of combining an early custom preflight with the framework's global name-based check. It discovers current and HKCU/HKLM legacy install roots, treats absent directories as clean, requests graceful shutdown from protocol-aware releases, and falls back to terminating only the old main executable and executables under its `resources` tree. This supports a direct 0.1.9-to-2.3.0 upgrade while preserving same-name applications and external plugin descendants. Windows integration tests cover missing roots, direct old processes, unrelated same-name processes, and detached descendants. Unit and end-to-end tests cover prompt persistence, the community action, secure IPC, accessibility, reduced motion, and one-version targeting.
