# Desktop 2.0 Design

## Product scope

Desktop 2.0 is a focused reliability and shell-polish release. It detects an incomplete packaged runtime before launching DSH, keeps the startup surface stable instead of entering a crash-and-restart loop, aligns the native Windows caption area with the injected title bar, removes the decorative startup dot, and gives the particle whale a restrained swimming path.

The startup whale remains inside the right side of the launch surface so it does not cross the product name, “探索未至之境”, status text, or recovery controls. Its body translates along a slow bounded path while the particle field gains slight heading, tail, and breathing motion. Reduced-motion users receive a static composition, hidden documents do not render frames, and frame density remains capped for integrated graphics.

## Runtime integrity

The desktop shell owns a small list of critical files that must exist in the unpacked runtime. The list includes the OpenTelemetry machine identifier module reported missing in the supplied log. The packaging verifier checks the same list before release, and the runtime controller runs a synchronous preflight before spawning DSH. A failed preflight produces a clear installation-repair message and does not schedule automatic restarts because no child process was launched.

This design treats the supplied report as an incomplete local installation rather than a defective release artifact: the published 0.1.9 installer contains the missing file, while the affected installation does not. Reinstalling can restore the file, and 2.0 makes the failure bounded and diagnosable if a security tool, interrupted upgrade, or filesystem problem removes it again.

## Conversation continuity

Desktop 2.0 keeps the existing queue-first interaction: a message sent while an agent is working is appended to the next-turn inbox and does not interrupt the active turn. The official runtime already promises that cancelling an active turn preserves this inbox and resumes it in FIFO order, but the current release can become idle without rearming its driver when messages were queued before cancellation.

A small host-only compatibility bundle observes idle agent transitions. When an idle agent still has next-turn messages, it re-arms the official agent driver without duplicating or reordering the queue. Recovery is guarded per agent and rechecks state in a microtask, so simultaneous status events cannot start parallel turns. It does not alter steering messages or the default queue-first behavior. The bundle uses only public DSH SDK services and can be removed after the upstream runtime implements the documented cancellation contract.

The same bundle normalizes the known code-tool cancellation string `code run failed (abort): [object Object]` to `当前执行已停止，排队消息将继续发送。`. It changes presentation only for the recognized user-cancellation failure and leaves unrelated tool errors untouched.

## Window chrome and startup surface

The injected drag bar uses the same opaque base colors as Electron's native `titleBarOverlay`. A subtle highlight remains above that base, but translucency no longer creates a visible depth change beside minimize, maximize, and close. Dark and light themes remain synchronized through the existing fixed IPC theme channel.

The startup brand contains only the product name and Desktop edition label. The blue circular `brand-mark` element and its CSS are removed instead of hidden, keeping the markup and accessibility tree minimal.

## Community plugin entry

Extension Dock contains a fixed, disabled-by-default community entry for `dsh-taffy-pet`, attributed to `zq123123667` and linked to its HTTPS GitHub repository. The desktop installer does not contain or republish the plugin's character images. Activating the entry opens the author's repository through a fixed main-process allowlist so the user can review the plugin, material terms, and installation instructions before adding it.

The entry is metadata rather than a protected built-in bundle. It cannot silently execute, contact a TTS service, or modify the desktop profile. A future package can become one-click installable after the author publishes a DSH bundle with declared compatibility and redistributable assets.

## Verification

Node and Vitest tests cover the runtime preflight, no-spawn failure path, shared package integrity list, FIFO queue recovery, cancellation error normalization, exact title-bar colors, startup markup, whale pose bounds, hidden-document suspension, community catalog allowlisting, and IPC routing. Playwright captures the startup surface and verifies native caption alignment. Directory packaging and package verification prove the compatibility bundle and critical runtime file are present in the distributable.
