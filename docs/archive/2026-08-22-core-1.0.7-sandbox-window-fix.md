# DeepSeek Harness Desktop 1.0.7 任务黑框修复记录

## 问题

安装 `1.0.6` 后，插件搜索和普通子进程路径已经隐藏，但智能体执行 `Pwsh` 任务时仍会弹出 Windows Terminal 黑框。

## 根因

`Pwsh` 工具在标准沙箱模式下会经过 `@deepseek-ai/dsh-sandbox-windows-acl`。该包使用 `CreateProcessAsUserW` 在受限令牌下二次启动 PowerShell。原实现的 `STARTUPINFOW.dwFlags` 只有 `STARTF_USESTDHANDLES`，没有指定隐藏首次窗口，因此无控制台的 Electron 宿主会触发 `OpenConsole`/Windows Terminal。

不能直接改用 `CREATE_NO_WINDOW`。官方实现已经记录：该标志会让此受限令牌下的 PowerShell 以 `STATUS_DLL_INIT_FAILED (0xC0000142)` 退出。

## 修复

- 为管道输出启动路径和继承输出启动路径同时增加 `STARTF_USESHOWWINDOW`。
- 将 `STARTUPINFOW.wShowWindow` 设为 `SW_HIDE`。
- 不修改受限令牌、ACL 授权、标准输入输出、Job Object 或退出码处理。
- 增加回归测试，要求两个 `CreateProcessAsUserW` 启动点都包含隐藏窗口设置，并禁止引入 `CREATE_NO_WINDOW`。

## 验证证据

- 未修复的 `1.0.6` 安装文件在无控制台 Electron 探针下新建了 `OpenConsole` 进程。
- 修改后的相同探针没有新建 `WindowsTerminal` 或 `OpenConsole` 进程。
- 修改后的受限 PowerShell 命令输出 `sandbox-hidden-ok`，退出码为 `0`。
- 针对窗口启动路径的 4 项回归测试全部通过。

## 发布要求

发布前必须继续通过完整单元测试、打包内容校验和打包启动冒烟测试。最终安装包版本必须为 `1.0.7`，不能覆盖已经发布的 `1.0.6` 标签和更新元数据。
